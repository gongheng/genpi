# 调试：四阶段根因流程

## 铁律

> 修任何 bug 前先找到根因。≥3 次修复尝试仍失败 → 停止第 4 次猜测，升级为架构审视。

## 四阶段

1. **复现（REPRODUCE）**：最小复现步骤，稳定复现；复现不了就没法验证修复
2. **定位（ROOT_CAUSE）**：数据流追踪——输入从哪来、每步怎么变、在哪一步走歪；提出假设并设计能证伪假设的观察
3. **修复（FIX）**：改根因不改症状；最小 diff；修完跑复现用例确认红转绿
4. **回归**：确认没引入新问题；补回归测试

## 反模式

shotgun debugging（改一堆碰运气） · "在我机器上是好的" · 只改症状不查根因 · 加 try/catch 吞掉异常让报错消失。
